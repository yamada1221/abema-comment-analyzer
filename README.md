# ABEMA Comment Analyzer

開発・検証の引継ぎは [AGENTS.md](AGENTS.md) を参照してください。2026-10-13のクラウドブラウザ検証は地域制限で停止しており、自動テストの成功と実放送での確認は区別しています。

通信経由のコメント取得と診断表示を追加しました。[取得方式・実機確認結果・制限](NETWORK-CAPTURE.md)を参照してください。

ABEMAのコメントをブラウザ内で記録・集計し、投稿者単位で分析・ミュートするChrome拡張です。

## v0.13.2 候補版（開発ブランチ・公開準備中）

新規インストールは記録OFFで開始し、既存版の記録設定は更新時に維持します。手動停止が自動監視で取り消される問題、バックアップ復元中の設定保持、復元前検査を改善しました。ABEMA以外のタブ情報へのアクセスを広げる `tabs` 権限を削除し、案内・データの取り扱い説明を追加しています。

この候補版は無料のChromeウェブストア公開に向けて準備中です。配布者情報・公開窓口・正式プライバシーポリシーと利用条件の確認が残っており、まだ申請・公開していません。寄付募集・課金・mainへのマージは保留しています。[配布準備記録](docs/distribution-readiness.md)と[国内Chromeでの確認手順](docs/local-validation.md)を参照してください。下のmain向けダウンロードリンクはv0.13.1で、この候補版は配布されません。

## v0.13.1 の変更

- **コメント検索**: 投稿者単位の検索に加え、本文に一致するコメントだけの一覧を追加。全半角・大文字小文字を区別しない部分一致、投稿者ID・番組名検索、ページ・投稿者タグ・ミュート状態での絞り込み、新旧順、100件ずつの表示、検索結果JSONに対応します。検索対象は上部で選んだ分析時間です。「保存分すべて」で保存期間全体を検索できます。
- **ユーザータグの自動付与**: 「絵文字のみ」「URLあり」「同文反復」「高頻度投稿」や、`災害情報: 地震, 津波` の追加ルールから、投稿者の既存タグに追加します。「疑問表現」の判定は削除しました。タグの検索・絞り込み・編集・書き出しを共通化し、コメント本文の検索は引き続き一致したコメントだけを返します。判定は保存履歴が対象で、同文反復は同じ本文が3件以上、高頻度投稿は自動ミュート設定の件数・秒数を使います。分析画面を閉じていても保存時に自動付与します。処理は端末内で行い、タグだけでミュートはしません。
- **タグの保持と削除**: 既存タグを優先し、合計12個まで追加します。タグは履歴の期限後・ルール削除後・自動付与OFF後も残ります。不要なタグはユーザータグ欄で外して保存すると、そのユーザーへの同名タグの再付与を止めます。手動で再追加すると除外が解除されます。
- **リプレイ**: 「現在の検索結果を読み込む」で、保存コメントを投稿時刻順に再生します。1〜60倍速、一時停止、先頭へ戻る、次のコメントへ移動、スライダーによる位置指定に対応。読込後の新着は混ざらず、直近100件を表示します。別タブへ移ると一時停止します。映像の再生・同期は含みません。投稿時刻が不明なデータは取得時刻を使い、画面に明記します。
- **絵文字ミュート**: 「自動ミュート」の「有効」と「絵文字だけの投稿者」をONにして保存してください。初期値はOFF、条件は120秒内に3件以上。取得済みの判定時間内の投稿がすべて絵文字のとき、投稿者をミュートします。件数は1〜100件、時間は1〜86,400秒で指定できます。数字だけ・通常文・顔文字は対象外で、投稿時刻が不明なコメントは数えません。除外ユーザー・判定履歴・取り消しに対応します。設定有効後の取得分を判定し、過去ログへの一括ミュートは行いません。
- **バックグラウンド**: 新着の到着時にも保存を開始し、保存中に届いた分も順に処理します。非表示への切替・ページ離脱時に保存を試み、約1分ごとの監視でも保存待ちを再試行します。記録ON中のABEMAタブはChromeの自動破棄を抑制し、OFF・他サイトへの移動時に元の設定へ戻します。監視アラームをワーカー起動のたびに作り直して延期していた問題も修正しました。
- **UI・引継ぎ**: 検索・リプレイ・投稿者分析を設定より上に移動し、各欄へのリンクを追加。長いIDやタグを折り返し、投稿者200人・個別コメント500件ずつの追加表示で大量データの描画を抑えます。保存形式6に更新し、自動タグ設定・再付与の除外・絵文字設定を引き継ぎます。v0.13.0の追加ルールは自動タグ設定に移行します。旧版ファイルに追加設定がない場合は現在の値を保持します。

Chrome・ABEMAタブを開いている必要があります。タブを閉じた後、ブラウザ終了中、端末のスリープ中は取得できません。ページ離脱直前の保存完了やABEMA側の通信継続は保証できません。画面上の接続表示は取得成功の保証ではなく、保存待ちや再読み込みの必要性を確認するためのものです。

## 主な機能

- 新着保存時にコメントを過去30日・最新100,000件へ整理してローカル保存（停止中は期限だけでは削除しない）
- 分析対象を「直近30分」「直近2時間」「直近7日」など任意に指定し、過去の基準日時にも対応
- ABEMAのコメント欄を上へ遡って過去コメントを取得
- 分析画面からABEMAのコメント欄を自動で開けるかテスト
- ABEMA NEWS・CNNjの指定時間帯、および番組名を指定した枠でABEMAを自動起動してコメントを記録
- 投稿者ID別ランキング
- 投稿者ごとのコメント一覧
- ユーザーID単位の複数タグ・タグ検索・絞り込み
- 指定時間幅に応じたコメント数推移グラフ
- 投稿者単位のリアルタイムミュート
- 連投・同文/類似連投・NGワードによる自動ミュート
- 自動ミュート理由と該当コメントの履歴表示
- 自動判定から除外するユーザー（ホワイトリスト）
- ミュート済みユーザーのコメント傾向を端末内で学習し、新しいミュート候補を検出
- 学習型ミュートの候補表示 / 高スコア自動ミュート
- バージョン間の引継ぎファイル書き出し / 読み込み
- JSON / CSVエクスポート

## インストール

1. 上の「main版v0.13.1をZIPでダウンロード」を押します。
2. ZIPを展開します。
3. Chromeで `chrome://extensions/` を開きます。
4. 「デベロッパーモード」をONにします。
5. 「パッケージ化されていない拡張機能を読み込む」を押し、展開したフォルダを選択します。
6. ABEMAの番組ページを開き、コメント欄を表示します。

## バージョンアップとデータ引継ぎ

### 同じフォルダを使って更新する場合

既存の拡張フォルダへ新版のファイルを上書きし、`chrome://extensions/` で「更新」を押してください。同じ拡張IDのままなら `chrome.storage.local` のデータはそのまま利用されます。

v0.5.0以降は保存形式のバージョン番号を持ち、同じ拡張ID内では必要なマイグレーションを自動実行します。

### 別フォルダへ新版を入れる場合

未パッケージ拡張はフォルダが変わると別の拡張IDになる場合があります。その場合は以下で引き継げます。

1. 旧版の分析画面を開く。
2. 「引継ぎデータを書き出す」を押してJSONファイルを保存する。
3. 新版をインストールする。
4. 新版の分析画面で「引継ぎデータを読み込む」を押す。
5. 旧版で保存したJSONを選択する。

引継ぎ対象:

- 保存コメント
- 手動ミュート一覧
- ユーザータグ（コメントの保存期限後も保持）
- 自動ミュート設定
- NGワード
- ホワイトリスト
- 自動ミュート履歴
- 学習型自動ミュートの管理情報
- 分析時間設定
- コメント記録ON/OFF
- 指定番組の自動起動設定

分析画面には現在の拡張バージョンと保存形式番号も表示されます。

引継ぎファイルは保存前にコメント・ミュート一覧・設定・履歴・学習データの形式を検証します。不正な項目がある場合は読み込みを中止し、既存データを保持します。旧版のファイルに含まれない項目も現在の値を保持します。正常なファイルに含まれる項目は復元元の値で置き換えます。

複数のABEMAタブから届くコメントはバックグラウンドで順番に保存し、同時保存による上書きを防ぎます。引継ぎの復元・保存データの消去も同じ排他処理を使います。一時的に保存に失敗した分は、タブが開いていて拡張機能が有効な間、次回の保存で再試行します。タブを閉じたり拡張機能を更新したりすると未保存分は失われる場合があります。30日・10万件への整理は新着保存時に行い、記録停止中やChrome終了中は期限だけでは自動削除しません。

## コメント欄の自動オープンテスト

分析画面の「コメント欄を自動で開くテスト」を押すと、開いているABEMAタブを検出し、コメントアイコンや「コメント」ラベルを持つボタンを探してコメント欄を開きます。

成功判定はクリック実行だけではなく、コメント入力欄・コメント一覧・ボタンの開閉状態などから、実際にコメント欄が開いたことを確認して行います。表示中のモーダルに「後で」ボタンがある場合は、そのモーダル内のボタンだけを先に閉じます。

指定番組の自動起動でも同じ処理を使います。自動確認とこのボタンの操作が重なった場合は、進行中のオープン処理を共有し、コメントボタンを重複して押さないようにします。

## 指定番組の自動起動

分析画面の「指定番組の自動起動」で、全体の「有効」をONにして設定を保存します。時刻・曜日は、端末のタイムゾーンに関係なく**日本時間**で判定します。

| 枠 | 曜日 | 初期の時間帯 | 記録開始条件 |
| --- | --- | --- | --- |
| ABEMA NEWSチャンネル | 毎日 | 00:01〜01:20 | 指定時刻に開始 |
| CNNj | 毎日 | 16:00〜16:20 | 指定時刻に開始 |
| 番組名を指定する枠（初期値：報道ステーション） | 火〜土 | 00:00〜02:00 | 画面で番組名を検出 |

- ABEMA NEWSとCNNjは `https://abema.tv/now-on-air/abema-news` を開きます。CNNjはABEMA NEWS内の放送枠として登録しています。放送編成の自動確認は行わず、設定した時間帯を記録します。
- 各枠を個別にON/OFFでき、開始・終了時刻も変更できます。番組名指定枠は、これまでどおり番組名・URL・曜日を変更できます。
- 更新時は既存の番組名・URL・曜日・時刻と全体の有効/無効を保持し、追加2枠をONの初期値で利用します。全体がOFFなら自動起動しません。追加枠をOFFにして保存すると、次の起動でもOFFを保持します。設定は引継ぎファイルに含まれます。
- Chromeのバックグラウンド処理が約1分ごとに時刻を確認します。Chromeが動作し、端末がスリープしていないことが必要です。開始・終了処理は次の確認時に行います。
- ページへの接続後、コメント記録をONにし、「後で」「あとで」の案内を必要に応じて閉じてコメント欄を開きます。時刻指定枠は番組名の一致を待ちません。
- 同じチャンネルの時間帯が重なる場合は1つのタブを共有し、最後の枠が終了するまで記録を続けます。たとえば報道ステーションの既存枠が02:00まで有効なら、ABEMA NEWS枠の01:20を過ぎても02:00まで続きます。01:20で終了させたい場合は番組名指定枠をOFFにしてください。
- 番組名指定枠が別チャンネルの場合、時刻指定枠を優先し、その終了後に番組名指定枠の監視を再開します。
- 番組名を一度検出した後は、表示を一時的に見失っても監視終了まで継続します。終了後は自動起動前の記録ON/OFF状態へ戻します。
- 「自動記録を手動停止」は、その時点で重なっている監視枠もまとめて停止します。別の時間帯の枠（深夜停止後のCNNjなど）は通常どおり起動します。設定を保存し直すと現在の時間帯も再開できます。
- 拡張が自動で開いたタブだけを終了後に閉じます（初期値ON）。元から開いていたタブや、別ページへ移動して使い直したタブは閉じません。起動タブは初期値では前面に出しません。

「現在のABEMAで番組名を確認」は、番組名指定枠の診断です。自動記録を開始せずに現在のABEMAタブで番組名判定を試せます。

## 過去コメントの取得

分析画面の「過去コメントを読み込む」を押すと、開いているABEMAタブを自動検出し、そのタブのコメント欄を上方向へ遡って過去コメントを取得します。

ABEMAタブは開いている必要があり、コメント欄も表示しておく必要があります。

## 自動ミュート

分析画面の「自動ミュート」で有効化します。初期状態では誤判定防止のためOFFです。

設定できるルール:

- 高頻度投稿: 例 30秒以内に8件でミュート
- 同文・類似連投: 空白・記号などを正規化した上で、例 60秒以内に3回でミュート
- NGワード: 1行1件で登録し、部分一致したコメントをしたユーザーをミュート
- 除外ユーザー: 1行1ユーザーIDで登録すると自動判定しません

自動ミュートされたユーザーは通常のミュート一覧にも入り、分析画面から解除できます。判定理由・該当コメント・時刻は自動ミュート履歴に保存します。

## 学習型ミュート

ミュート済みユーザーのコメントを学習例として、未ミュートユーザーのコメント傾向がどの程度近いかを端末内で計算します。

- 日本語の形態素解析や外部AI APIは使わず、文字2〜3gram + TF-IDFで特徴を作ります。
- 通常ユーザーにも多い表現は減点し、ミュート済みユーザー側に特徴的な表現を重視します。
- 1コメントだけでは判定せず、ユーザーごとの最低コメント数を設定できます。
- まず候補だけ表示し、確認して手動ミュートできます。
- 必要なら高スコアの候補だけ自動ミュートできます。
- 自動ミュートで新たに追加されたユーザーは、そのまま次の学習元には使わないため、誤判定が連鎖しにくい設計です。
- 候補ごとに類似度と、判定に寄与した文字パターンを表示します。
- ホワイトリストへ追加すれば、以後の候補判定・自動ミュートから除外できます。

学習型ミュートは初期状態OFFです。分析画面で有効化し、候補しきい値と自動ミュートしきい値を調整してください。コメント内容と学習処理は外部へ送信されません。

## ユーザータグ

投稿者ランキングでユーザーを選び、「ユーザータグ」に好きな名前を入力して「タグを保存」を押します。

- カンマ・読点・改行で複数のタグを区切れます。1タグ32文字、1ユーザー12個までです。
- 「要観察」「定型文」「掛け合い」「連投」はボタンでも追加できます。同じタグは重複登録されません。
- ランキングにタグが表示され、「タグで絞り込み」や検索欄で探せます。
- 「タグ付きユーザー」または個別タグを選ぶと、現在の分析時間内にコメントがないユーザーも0件で表示します。
- 未収集のIDも「IDを指定してタグを編集」から登録できます。
- タグを外して保存すると削除されます。「すべて外す」は「タグを保存」で確定します。外したタグは、そのユーザーには自動で付け直しません。手動で追加し直すと除外が解除されます。
- タグはミュートとは独立しています。付けただけではミュートや学習判定は変わりません。
- コメントの30日保存期限を過ぎてもタグは残ります。ユーザーIDが変わった場合は別ユーザーとして扱います。
- JSON・CSVのコメント書き出しにも、その時点のユーザータグを含めます。コメントがないユーザーのタグまで保存する場合は、引継ぎデータを書き出してください。
- 引継ぎファイルに全ユーザータグを含めます。タグのない旧版の引継ぎファイルを読む場合は現在のタグを保持します。タグを含む新版の引継ぎではタグ一覧も復元元で置き換えます。
- 編集中にコメントが追加されてもタグの入力は保持されます。別画面で同じユーザーのタグが変更された場合は、保存時に知らせます。

## 開発時のテスト

Node.js 24.15以降で `npm ci`、`npm test` を実行します。テスト用の依存関係は拡張機能の実行には不要です。

タグの保存・削除、旧版からの引継ぎ、コメント期限後の保持、複数画面の同時編集、入力検証を確認します。画面のテストはDOM環境とChromeストレージの模擬実装を使うため、実際のChromeとABEMA上での確認は別途必要です。

## データについて

コメントデータ、ミュート設定、自動ミュート設定は `chrome.storage.local` に保存され、外部サーバーには送信しません。

引継ぎファイルにはこれらのデータが含まれるため、第三者へ渡さないでください。

高コメント量の番組では最大100,000件の保存上限に先に達する場合があります。


## v0.9.0: 学習用データの継続保存

学習型ミュートを有効にすると、ミュート済みユーザーの学習用サンプルを閲覧履歴と別に保存します。閲覧履歴が24時間で消えても学習元を保持できます。旧版ですでに失われたコメントは復元できません。

- 最大200人、1人40件。新しい投稿を優先し、各サンプルは正規化済みの最大160文字です。端末内にのみ保存します。
- 学習元ごとの重みは最終サンプルから30日で半減。180日を超えたサンプルは対象外になり、次回の保存更新で削除します。類似度は確率ではなく、同じ話題による誤判定は引き続きあり得ます。
- ミュート解除・ホワイトリスト指定でその人の保存サンプルを削除。学習による自動ミュート済みユーザーは学習元にしません（既存のルール型自動ミュートは学習元に含みます）。
- 学習を無効にすると新しいサンプルの蓄積を停止します。既存サンプルは保持しますが、解除・除外・期限は反映します。
- 候補判定と一般ユーザーとの比較には現在の保存コメントを使います。古いユーザーを候補として再表示しません。
- 引き継ぎファイルに学習用データを含めます（保存形式3）。旧形式の取り込みでは既存の学習用データを保持し、復元したミュート・除外設定に合わせて整理します。

更新前に引き継ぎファイルを保存してください。更新後はABEMAタブを再読み込みしてください。

## v0.9.2: 高頻度ミュートの誤判定対策

- 投稿日時が不明なコメントは高頻度・同文連投の自動判定に使いません。取得時刻への置き換えで過去コメントを連投と誤認するのを防ぎます。NGワード判定は継続します。
- 指定秒数の前後両側を数える処理を修正し、実際に指定秒数内に収まる投稿だけを数えます。取得順序が前後する場合も対応します。
- 同一コメントIDの重複通知は加算しません。自動ミュート履歴に、判定対象の開始・終了時刻と実際の秒数を保存します。
- 既存のミュートは自動解除しません。誤判定されたユーザーは確認のうえ解除してください。拡張更新後はABEMAタブを再読み込みしてください。

## v0.9.3: 自動ミュート判定の取り消し

「自動ミュート履歴」の各行で「このユーザーの判定を取り消す」を押すか、判定の種類・日付（日本時間）で絞り込み、対象を選択して一括取り消しできます。履歴は最新500件まで保持し、条件に合う保存済み履歴をすべて表示します。

取り消しはユーザー単位です。同じユーザーの未取消の自動判定をすべて取り消し済みにし、ミュートを解除し、学習用サンプルを削除します。手動でもミュートした場合はそのミュートも解除されるため、実行前の確認画面で対象を確認してください。

対象は「自動判定から除外するユーザーID」に追加されます。連投・NGワード・学習型を含む自動判定で再ミュートしません。再び自動判定したい場合は、除外リストからIDを削除して設定を保存してください。手動ミュートは引き続き使用できます。

履歴の取消状態と除外設定は引き継ぎデータに含まれます。更新後は拡張機能とABEMAタブを再読み込みしてください。v0.9.2の高頻度誤判定対策も含みます。


## v0.10.0: 過去のコメントを見返す

新着保存時に過去30日・最新100,000件へ整理するように拡大しました。保存期間は取得時刻基準です。取得時刻がないデータは投稿時刻で判定します。記録停止中やChrome終了中は期限だけでは削除しません。上限を超えると保存時に古いコメントから削除します。

- 分析期間の単位に「日」を追加。「保存分すべて」で、保存済みの最新コメントから30日間を表示します。
- 「基準日時（日本時間）」に例として2026/9/26 01:00を指定し「1時間」で適用すると、その日の00:00〜01:00を表示します。空欄では最新コメントが基準になります。基準日時の指定は画面を閉じるまで有効です。
- コメントに日本時間の日付・時刻を表示します。保存中の最古・最新日時も確認できます。書き出し対象は選択した分析期間です。
- 更新前に削除されたコメントは復元できません。ABEMAの過去コメント取得範囲はABEMA側が表示・提供する範囲に限られます。
- 長期保存のためunlimitedStorage権限を追加しています。端末内の保存領域だけに使用し、外部送信はしません。ディスク使用量はコメント量に応じて増えます。
- 更新前に引き継ぎデータを保存し、更新後は拡張機能とABEMAタブを再読み込みしてください。

自動ミュート判定取り消し機能と、高頻度判定の誤判定対策も含みます。

## v0.11.0: 問題になったコメントだけを学習元に指定

投稿者ランキングでユーザーを選び、右側のコメントにある「このコメントを学習」を押します。ミュート済みかどうかに関係なく指定でき、指定する操作でミュート一覧・自動ミュート設定・タグは変更しません。

- 指定が1件以上ある間は、指定した文章だけを学習元に使います。従来のミュート済みユーザー全員の文章と混ぜません。指定例を全件解除すると従来の学習に戻ります。
- 明示的に選んだ文章は1件から利用できます。「学習に必要なミュートユーザー数」は従来の学習だけに適用します。比較対象の「候補判定に必要なコメント数」は引き続き適用します。
- 保存中の各ユーザーの直近最大40件を、指定した文章ごとに比較します。「指定文との類似度」（初期値70%）以上の別々の投稿が2件以上あり、平均類似度が候補しきい値以上なら候補に表示します。選択した元の投稿と重複通知は件数に含めません。通常ユーザーに共通する表現を減点し、ミュート中・除外中のユーザーは候補にしません。
- 推薦候補の「一致した投稿」を開くと、実際の投稿、学習元のユーザーIDと指定文、類似度を確認できます。意味による分類ではなく文字の似かたを使うため、候補の根拠を確認してください。
- 「学習型ミュート」を有効にして設定を保存すると推薦に反映します。学習を無効にしても指定文は保持します。「高スコアを自動ミュート」の既存設定を有効にしている場合は、その設定としきい値に従って自動ミュートされます。まずは候補表示のみで確認できます。
- コメント横の「学習指定を解除」、または「指定した学習コメント」の一覧から指定を解除できます。解除後に古い判定結果が届いても、解除された指定文による自動ミュートは保存しません。
- 指定文は履歴の保存期限やミュート解除後も残ります。最大200件、本文は1件4096文字までで、不要な指定は手動で解除します。外部への送信はしません。
- 引継ぎファイルに指定文を含めます（保存形式4）。v0.10.0以前のファイルを読み込む場合は、既存の指定文を保持します。不正な指定文を含む引継ぎは、既存データを書き換えずにエラーにします。

更新後は拡張機能とABEMAタブを再読み込みしてください。v0.10.0の引継ぎデータ・ミュート一覧・タグ・設定をそのまま利用できます。

## v0.11.2: 自動記録の開始・停止を安定化

- 定期確認・設定変更・手動停止を順番に処理し、タブの二重起動や停止後の記録再開を防ぎます。
- 停止・設定変更前に行った番組判定の結果は無効にします。判定を待つ間に監視終了時刻を過ぎた場合も記録を開始しません。
- 休止中に監視枠をまたいだ場合や対象URL・番組名を変えた場合は、前の記録を終了してから新しい監視を始めます。自動起動前の記録ON/OFF状態を保ちます。
- 元から開いていたタブや、別ページへ移動して使い直したタブを閉じません。
- コメント欄を開く処理が重なってもボタンを1回だけ押し、表示が遅いときに開閉を繰り返してしまう問題を防ぎます。

Chromeでの回帰テストでは、ネットワークをオフラインにし、ABEMA URLの応答をテスト画面へ差し替えています。実際の拡張機能を使って「あとで」「後で」の案内を閉じること、コメント欄が開くこと、取得したコメントが保存されることを検証します。ABEMA本番の最新画面での動作確認とは別の検証です。

ZIPを更新後、拡張機能とABEMAタブを再読み込みしてください。保存済みコメント、タグ、学習指定、ミュート設定は引き続き利用できます。

## v0.12.1: 再接続時のコメント欄表示

番組名を検出して記録を開始した後、番組名表示を見失っている間にタブを開き直すと、記録設定だけがONになりコメント欄を開かない場合がありました。継続記録中もコメント欄を開く要求を送り、再接続・再読み込み後に表示を復旧するよう修正しました。すでに開いているコメント欄は閉じません。番組名未検出の初期待機中は記録を開始しません。
