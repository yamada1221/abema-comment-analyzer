# 国内Chromeでの確認手順（v0.13.2候補版）

2026-10-20作成。一般配布・ストア申請・mainへのマージ・寄付募集・課金は保留。
この手順は本人のPC内での確認用。確認していない欄は未実施のまま残す。

## 用意するもの

- 日本国内でABEMAを視聴できるPC版Chrome。Chromeのバージョンと実施日時を記録する。
- `python scripts/package_extension.py` で検査・生成したレビューZIPを `dist/review-unpacked/` に展開したもの。
- 新規確認にはChromeのテスト用プロファイルを使う。既存の拡張・記録と混同しない。
- 既存版を更新する場合は、先に旧版の分析画面から引継ぎファイルを書き出し、安全な場所に保管する。ファイルや実コメントをGitHubへアップロードしない。

## まず確認すること

1. Chromeの `chrome://extensions` でデベロッパーモードを有効にし、「パッケージ化されていない拡張機能を読み込む」から `dist/review-unpacked` を選ぶ。v0.13.2であることを確認する。
2. 拡張のポップアップが「記録を開始」、保存件数0件であることを確認する。案内・データの取り扱いを開けることも確認する。
3. ABEMAのコメントが流れる番組を開き、コメント欄を表示する。初回同意等は本人が内容を読んで操作する。記録OFFのまま60秒以上待ち、保存件数0件を確認する。
4. ポップアップの説明を読み、「記録を開始」。ABEMAタブを再読み込みし、コメント欄を開く。表示コメントが流れる間に保存件数が増えることを確認する。
5. 「記録を停止」。件数が安定した後、60秒以上待って増えず、ABEMAタブが開いたままであることを確認する。

この5項目の結果だけでも、日時・Chromeバージョン・合否・止まった箇所を記録する。地域制限が出た場合は中止し、回避しない。

開発版の更新では拡張を「削除」しない。別フォルダーを読み込むと通常は拡張IDが変わるため、更新保持テストの証拠にならない。Chromeの同一プロファイル再起動だけでも更新テストの証拠にならない。

記録ON・OFFの両方で更新を確認する。古い版で記録フラグが存在しない場合のON移行は自動テストでも確認する。新規インストールの初期OFFとは分けて扱う。

## 2026-10-20の本人による確認結果

- 対象はv0.13.2候補版、コード基準 `fd99e4a` のローカルレビュー一式。
- 本人が「初期状態が記録OFF」「ABEMAの実コメントを記録できる」「停止後60秒以上待っても件数が増えない」の3点について、すべて確認できたと回答した。
- 確認日時は2026-10-20（日本時間）。Chromeバージョン・プロファイル詳細・実施時刻は未申告。コメント本文・投稿者IDは受領していない。
- 続いて本人が本文検索・タグ保存・リプレイ・ミュート→解除の4機能も確認できたと回答。細かな操作条件まで報告がない項目（開始前の無保存、記録OFF中のミュートなど）は完了へ広げない。
- 本人の手元には今回のv0.13.2だけが入っており、旧版v0.13.1は未導入との回答。自動起動・復旧・更新・ストア経由の配布は未確認。
- Codexの操作対象としてChromeは未接続。上記は本人の手動確認報告であり、Codexによる直接操作や模擬ChromeのCI結果とは区別する。

## 旧版が手元にない場合の更新確認

2026-10-20、更新用に固定した旧版コミット `7da43d9` の実行ファイル19個を `dist/local-update-check/extension/` に展開した。現時点の状態は旧版準備済みで、更新完了ではない。

1. 今回確認したv0.13.2を残し、拡張機能のない別のChromeテスト用プロファイルを使う。2つの版を同じABEMA画面で同時に動かさない。
2. 上記フォルダーを拡張機能として読み込み、バージョン0.13.1を確認する。**この旧版は初期記録ON**。初期OFFへの改善前の実装であり、新規利用向けには使わない。
3. コメントを1件以上保存して記録を停止する。タグとミュート対象を各1件設定し、件数・拡張ID・番組設定を手元に控える。自動起動はOFFにする。コメント本文・IDやバックアップの提出は不要。
4. 準備できたと本人から返答があった後に、CodexがレビューZIPの26ファイルを**同じ読込元フォルダーへ**書き込む。ユーザーのChromeプロファイルや保存データへは触れない。
5. Chromeでその同じ拡張機能の「再読み込み」を押す。削除や別フォルダーからの再追加はしない。
6. v0.13.2になり、拡張ID・記録OFF・件数・タグ・ミュート・番組設定が維持されたことを確認する。別途、記録ONのままの再読み込みでも設定を維持するか確認する。後者がv0.13.2同士の再読み込みなら、その範囲で記録する。

これは開発版のローカル更新確認であり、署名済みChrome Web Store更新とは区別する。実行用スクリプトと途中状態のメタデータはローカルの `test-results/`・`dist/` にのみ保存し、Gitへ登録しない。
