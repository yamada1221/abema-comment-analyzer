## Chromeウェブストアで確認できたこと

2026-10-20に現行の公式ポリシーとFAQを再確認。端末内だけで処理・保存する場合にもデータの扱いの開示とプライバシーポリシーが必要で、権限は既存機能に必要な最小限とする。保存するデータ・用途・保持・削除の説明を実装と一致させる。以前の記録にあったブログの告知日・適用日の記述は今回再確認できなかったため、判断の根拠には用いない。

- [Chrome Web Store Program Policies](https://developer.chrome.com/docs/webstore/program-policies/policies)
- [Chrome Web Store ユーザーデータFAQ](https://developer.chrome.com/docs/webstore/program-policies/user-data-faq)

現在の対応:
- 新規インストール時のコメント記録をOFFにするだけでなく、**保存フラグが未確定の場合も記録しない**ように修正した。更新時は古い暗黙のON設定をONへ移行し、既存利用者の記録選択を変えない。
- ポップアップの「記録を開始」の前に、収集データ（コメント本文、投稿者ID、日時、ページ情報）とローカル保存・開発者への非送信を表示。ストレージ読込完了前はボタンを無効化。
- 引き続き公開URLのプライバシーポリシー、配布者の連絡先、データ開示項目、Chrome Web Storeの許可権限の説明を準備する。

注意: `network-bridge.js` のフック自体はページ読込時点で設置されるものの、記録OFF中は通信応答の解析・診断送信を抑止する。`page-bridge.js` も、記録OFFかつミュート対象なしの場合はDOM走査用のObserver・タイマーを稼働させない。利用者がミュート対象を指定している場合は、**ローカル表示制御のために該当コメントのDOMを読み取る**が、記録OFFならコメントを保存・送信しない。記録ON/OFFの切替とミュートリスト更新後にもObserverを整理する。これはDOM解析コードの改修と模擬環境テストであり、Chrome実放送での確認・Chromeの審査通過を意味しない。

## v0.13.2候補版の権限・説明の照合

- [Chrome Tabs APIの権限説明](https://developer.chrome.com/docs/extensions/reference/api/tabs#permissions)では、対象ホストの権限があれば、そのサイトのタブのURL・タイトルを取得できる。タブの作成・更新などのAPI利用自体は広域の `tabs` 権限を必要としない。
- ABEMA以外のタブのURL・タイトルへのアクセスを広げる `tabs` をManifestから除いた。対象ホストは `https://abema.tv/*` だけ。`storage`・`alarms`・`unlimitedStorage` は履歴・設定、番組監視、大量のコメント保存に利用する。パッケージ検査は `tabs` が再追加されても拒否する。
- 模擬ブラウザにABEMAと無関係なサイトを開き、ABEMAタブの検索と自動破棄設定の操作ができ、無関係なURL・タイトルを拡張から読み取れないことを検証する。
- `background.js` の保存処理は新着保存時に30日・10万件へ整理する。期限だけで定期削除する実装ではないため、`guide.html`・`privacy.html`・ポリシー草案・掲載文案を修正した。復元した古い履歴も次の新着保存までは残り得る。
- [Chrome公式FAQ](https://developer.chrome.com/docs/webstore/program-policies/user-data-faq)の問3・14は、端末内でのみ処理・保存する場合にもデータ取扱いの開示とポリシーを要求している。外部送信がないことを理由に申告を省略しない。
- 配布者名・問い合わせ先・公開URLは2026-10-20に本人へ確認し、いずれも未定。正式ポリシーとしての公開・登録はしていない。

これはManifest、通信観測、保存・削除・出力の処理と表示説明の確認記録。全コードの安全性やストア審査適合性の保証ではない。
